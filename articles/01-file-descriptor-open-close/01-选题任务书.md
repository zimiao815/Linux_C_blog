# 文件描述符与打开关闭

- 核心问题：`open` 返回的那个整数（fd）到底是什么，`close` 之后发生了什么？
- 一句话结论：fd 是进程内一张「打开文件表」的索引，open 返回的是当前最小的未用编号；close 释放这张表里的一格（而非立即销毁文件对象），只有最后一个引用被释放时底层资源才真正回收，此后编号可被复用。
- 适用条件 / 范围：POSIX 通用语义；「fd 是最小未用编号」是 POSIX 保证；「close 后底层 file 结构何时销毁」取决于引用计数（Linux 实现）。示例在 Linux/macOS 上均可复现。
- 不处理：read/write 短读短写（第 2 篇）、lseek 定位与 O_APPEND（第 3 篇）、dup/dup2 复制（第 4 篇）、fsync 落盘（第 5 篇）；本片只讲 fd 这个「句柄」本身的打开与关闭语义。
- 四类读者视角（各一句话）：
  - 搜索者：open 返回的负数/整数是什么意思，close 之后这个编号还能不能用。
  - 学习者：fd 背后是「进程打开文件表 → 打开文件描述 → inode」三层结构，close 减的是引用计数。
  - 编程者：close 返回值要检查、失败后不能重试、多线程里不能随手 close。
  - 求职者（按需）：fd 与 FILE* 的区别、close 失败为什么不能 retry、fd 复用竞态。
