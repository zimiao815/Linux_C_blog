# 研究记录（选题1：文件描述符与打开关闭）

## 核心判断

fd 是「进程打开文件表」的整数索引；open 返回最低未用编号；close 递减引用计数，只有最后一个引用释放时底层打开文件描述（open file description）才销毁。这些是 POSIX 保证，Linux 实现为「fd 表 → struct file → inode」三层。

## 材料卡片

| 结论 | 来源 | 支撑程度 |
|------|------|----------|
| open 返回「最低未用编号」 | Linux man-pages open(2)：「The file descriptor returned by a successful call will be the lowest-numbered file descriptor not currently open for the process.」 | 强（POSIX 保证） |
| file offset 初始为文件开头（0） | open(2)：「The file offset is set to the beginning of the file」 | 强 |
| close 删除描述符，最后一个引用释放时对象销毁 | macOS close(2)：「deletes a descriptor from the per-process object reference table. If this is the last reference... the object will be deactivated」；Linux close(2) 同义 | 强 |
| close 返回值必须检查，写错误可能推迟到最后一次 close 才报告 | Linux close(2) CAVEATS | 强 |
| close 失败后不能 retry（fd 已被释放可复用） | Linux close(2) CAVEATS：「the Linux kernel always releases the file descriptor early... Retrying the close() after a failure return is the wrong thing to do」 | 强 |
| close 的 EINTR：Linux 保证 fd 已关，POSIX 说状态未指定，POSIX.1-2024 改为 HP-UX 行为 | Linux close(2) CAVEATS | 强 |
| 多线程 close 竞态：fd 复用导致误关 | Linux close(2) CAVEATS | 强 |
| fd 上限 RLIMIT_NOFILE，超限报 EMFILE | open(2) ERRORS + getrlimit(2) | 强 |
| open 常见错误：ENOENT / EACCES / EMFILE / ENFILE | open(2) ERRORS | 强 |

## 实验记录

环境：macOS (Darwin 23.6.0, x86_64)，Apple clang 16.0.0。
编译选项：`cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。

### 实验 A：fd 复用（fd_reuse.c）

```
fd1 = 0, fd2 = 5
close(0) 后再 open，拿到 fd = 0
```

结论：close(0) 后首次 open 拿到 0（最低未用）；close 释放后编号立即可复用。fd2=5 是 macOS 运行时额外占用 fd 1-4 所致（平台差异，Linux 上 close(0) 后连续 open 得 0、1）。

### 实验 B：偏移量独立（fd_offset.c）

```
fd1 read 1 byte: 'a'
fd2 read 1 byte: 'a'
fd1 offset = 1, fd2 offset = 1
```

结论：同一文件 open 两次得到两个独立的偏移量，各读到 'a'、偏移各自为 1——证明两次 open 指向不同的 open file description（而非共享一个）。

## 矛盾与处理

- macOS 第二次 open 拿到 fd=5 而非 1：因 macOS 动态链接器/运行时启动时占用了 fd 1-4。已在正文如实标注为平台差异，不硬套 Linux 编号。
