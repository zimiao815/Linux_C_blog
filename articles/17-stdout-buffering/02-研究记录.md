## 实验环境和编译

macOS 14.8.8 x86_64，Apple clang 16.0.0。参数为 `-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。源文件 `stdout_buffer.c` 在临时干净目录中编译，零警告。

核心程序先 printf，然后向独立 stderr 输出并刷新检查点，接着等待 stdin 的一个字节；最后输出 done、检查 stdout 刷新。读取被 EINTR 中断时重试。使用 POSIX read 的 stdin 没有同时经过 stdio，stdout 的业务字节全部走 stdio。

## 自动采样方法

`verify.py` 为每组创建新进程。stdout 分别接 PTY、普通文件和管道。PTY 设置 raw，避免终端把 LF 改成 CRLF；stdin 始终使用独立管道作闸门，stderr 管道作检查点同步。

父进程收到检查点后，确认子进程尚未退出，读取 stdout 目标中已经可见的字节。采样结束才给 stdin 发送换行，读取最终输出并核对退出状态。

macOS 的 PTY 最后一个 slave 关闭后可能丢弃尚未读取的输出，因此采集器保留父进程的 slave 引用直到最终读取完成；这不更改子进程的 stdio 缓冲策略。初版采集器过早关闭 slave 导致末段缺失，修正采集器后重新执行全部案例，最终记录均来自通过后的执行。

九组结果见 `verification.json`、`actual-output.txt`；面向正文的对照表由这些数据生成，保存为 `observations.md`。

- newline：终端在闸门前收到 ready 加换行，文件和管道未收到字节。
- partial：三个目标在闸门前均未收到字节。
- flush：三个目标在闸门前均收到 ready 加换行。
- 放行后 newline/flush 收到 ready、done 两行；partial 收到 ready> done 一行。九组均退出 0。

## 失败案例

- stdin 提前结束：报告 stdin ended before release，退出 1。
- 参数非法：输出用法，退出 1。
- stdout 接普通文件，子进程 RLIMIT_FSIZE=0 且忽略 SIGXFSZ：newline 到达检查点后在最终 fflush 报 File too large；flush 在检查点之前失败，退出 1。
- stdout 使用只读描述符：显式刷新报 Bad file descriptor，退出 1。
- 持续故障时，错误后的统一收尾可能再次尝试 fflush 并再次报告错误；正文已说明。没有把第一次刷新失败后的操作误写成成功。

## 证据边界

未在 Linux 主机运行，未跟踪系统调用，未测缓冲容量，不依赖固定 4096/8192 字节。未模拟 stdout 在启动后被 dup2 改接目标、非阻塞流、管道消费者提前退出、多线程、进程复制、异常终止或断电。本例对错误报告并退出，不是完整的输出恢复协议。

正常 exit 自动刷新的结论来自规范；主实验结束前显式 fflush，因此不把其最终输出单独当作自动退出刷新的实验证据。
