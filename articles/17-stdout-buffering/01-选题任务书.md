# 标准 I/O 库第 3 篇：标准输出的缓冲

- 核心问题：为什么同一段 printf 在终端和重定向到文件时表现不同？
- 一句话结论：默认 stdout 在终端上通常行缓冲，在普通文件或管道上通常全缓冲；换行触发行缓冲的提交，及时输出应明确 fflush 并检查结果。
- 条件：新进程默认标准流，小量输出，未调用 setvbuf，未在运行中修改 stdout 目标；Linux/glibc 机制以指定版本源码为依据。
- 前置：第 1 篇的 FILE 对象、缓冲与 fd 关系。
- 不展开：setvbuf 配置细节、完整刷新持久化链路、fclose 关闭教程、fork 重复输出、线程锁、stdio 与系统调用在同一流上的混用。
- 搜索者：用终端/文件/管道三个目标复现差异，并知道如何及时提交。
- 学习者：理解缓冲在用户态，默认策略与实际目标有关。
- 编程者：在交互边界刷新，检查写入和刷新失败。
- 求职者：能区分 stderr 不全缓冲与 glibc 无缓冲，也能说明正常退出的限制。

## 实验设计

通过检查点与输入闸门控制观察时刻，避免 sleep 引入时间猜测。stdout 三个目标乘以带换行、无换行、显式刷新三个选项，共九组。stderr 独立且显式刷新，仅用于同步，不把诊断字节算作 stdout。

## 标题候选

- 搜索型：stdout 重定向后的 printf 为什么不立即输出？
- 通俗型：程序已经打印了，文件为什么还是空的？
- 兼顾型：printf 加了换行，重定向后为什么还是没输出？
- 采用兼顾型，强调本篇能用实验回答的具体困惑。
