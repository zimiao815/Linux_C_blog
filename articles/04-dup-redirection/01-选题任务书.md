# `dup`/`dup2` 与重定向

- 核心问题：`dup` 复制的是文件描述符，还是同一个打开文件对象？标准输出重定向为什么能生效？
- 一句话结论：`dup`/`dup2` 新建的是文件描述符表项，但新旧 fd 指向同一个打开文件描述（Linux 内核中的 `struct file`）；因此共享文件偏移量和文件状态标志。`dup2(oldfd, newfd)` 还会先让 `newfd` 指向 `oldfd` 的同一对象，所以把 `newfd` 设为 `STDOUT_FILENO` 就能把后续标准输出导向文件。
- 适用范围：POSIX `dup`/`dup2` 与 Linux/Unix 文件描述符语义；实验在 macOS 14.8.8、Apple clang 16 上验证。
- 不处理：`dup3` 的 Linux 特有参数、shell 解析顺序、跨进程同步和 `fcntl` 文件锁。
