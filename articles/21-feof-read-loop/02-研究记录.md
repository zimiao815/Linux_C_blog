## 事实依据

| 关键判断 | 一手来源 | 适用范围 |
| --- | --- | --- |
| feof / ferror 检查 FILE 的结束 / 错误标志，返回非零而非保证 1 | POSIX.1-2024 feof / ferror，glibc EOF and Errors | 正文输出先转换成 != 0；查询不预测后续读取 |
| fgetc 无数据可能是结束，也可能是错误；两种结果都可返回 EOF | POSIX fgetc RETURN VALUE | 成功返回 unsigned char 转 int；本篇只简述，不展开后续返回类型篇 |
| 新流首次读取前的 EOF 标志未置位；读完最后字节后下一次尝试发现结束 | 实际空文件和单字节实验；POSIX fgetc；glibc fileops.c | 限定本篇逐字节实验，不推广为所有读取函数的最后一份数据返回时机 |
| 发生错误时 EOF 标志不一定置位，错误条件可能被 !feof 循环遗漏 | POSIX fgetc，实际目录错误及有上限探针 | 目录打开成功并读错是本机行为，不作为所有平台必然表现 |
| 有效流上的 feof / ferror 不改变 errno | POSIX feof / ferror 的 CX 扩展 | 主程序先查 ferror，只有确认为错误才保存 errno，后续再诊断 |
| glibc 状态位为 _IO_EOF_SEEN / _IO_ERR_SEEN | glibc 2.40 feof.c / ferror.c / struct_FILE.h | 内部字段，不是可移植应用 API |
| 缓冲不足时普通文件 underflow 调用底层读取，正数补缓冲、零置 EOF、负数置 error | glibc fileops.c _IO_new_file_underflow | 已有 EOF 时可直接返回 EOF；不声称每次 fgetc 均调用 read |
| Linux fd 表到 struct file / inode 的对象关系 | Linux v6.6 fdtable.h / fs.h | 图是源码结构示意，非 macOS 运行快照 |
| clearerr 清除两个标志，不定位；成功 fseek 清除 EOF 标志 | POSIX clearerr / fseek；eof_state.c 实测 | 不把 fseek 写成同时清除 error，不把 clearerr 写成修复错误 |
| fgets 可能返回末尾有效字符串并遇到 EOF；fread 依据实际元素数量处理 | POSIX fgets DESCRIPTION / RETURN VALUE，fread RETURN VALUE | 提醒不要把字节读取时机套用到所有输入接口；不展开长行与元素计数主题 |

## 实验复现

```sh
/Users/zhaodan/.workbuddy/binaries/python/envs/default/bin/python linux_c_blog/articles/21-feof-read-loop/verify.py
```

- 实际系统：macOS 14.8.8 x86_64；Apple clang 16.0.0。
- 严格编译三个 C 程序：`-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`，无警告。
- 验证器在全新临时目录构建和运行，每个子进程有超时，临时文件自动清理。
- 主程序只读取输入，不改写输入。stdout 是观察结果，stderr 是错误诊断。

12 次执行分组如下：

1. 四种正常输入：空文件、A、A 换行、二进制 00 FF。成功读到的数据数量为 0 / 1 / 2 / 2，结束均 feof=1 / ferror=0，退出 0。
2. 四条失败路径：缺参数、不存在的文件、目录读取失败、stdout 文件大小限制为 0。均退出 1。目录读错为 EISDIR 的本机错误文本 Is a directory，状态 feof=0 / ferror=1。输出失败由 fflush stdout 报 File too large，未误报成功。
3. 三个有限探针：空文件进入 1 次，单字节进入 2 次（第二次得到 EOF），目录读错连续 3 次 feof 仍为 0 后触发上限。不会无限运行，也没有把 EOF 作为字节处理。
4. 一个状态恢复实验：tmpfile 写 A 后通过 fseek 合法切换到输入；读字节后 EOF=0，再读得到 EOF=1；再次读取仍 EOF=1；clearerr 后 EOF=0，再读又 EOF=1；fseek 到头后 EOF=0，重新读出 A。

## 代码与解释核对

- 主程序以 fgetc 返回值控制循环，类型为 int；ferror 优先判定，保留意外的双零状态检查。
- 根据 POSIX ferror 不修改 errno 的明确规定，最终版把 errno 保存放在 has_error 判定之后。修改后重新从干净目录编译并执行全部验证。
- 所有输出、输入文件关闭、最终 stdout 刷新均纳入退出状态；资源只关闭一次，关闭之后不查询流状态。
- bad_loop_probe.c 是故意保留错误条件的有界观察器，不是推荐代码，不含无界循环或无效字节处理。
- eof_state.c 只在合法的更新流切换后读取；不依赖未定义行为。
- 正文输出和观察表由 compose_article.py 从 verification.json 装配。
- 示例未使用 feof 预估文件大小或剩余字节；没有声称 EOF 是磁盘中的特殊字符。
