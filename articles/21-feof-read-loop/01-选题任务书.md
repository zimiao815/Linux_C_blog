# 标准 I/O 库第 7 篇：feof 与读取循环

- 核心问题：为什么不能只靠 while (!feof(fp)) 控制读取？
- 结论：feof 查询已记录的 EOF 标志，不预测读取；让读取返回值控制数据处理，停止后先检查 ferror，再识别正常文件结束。
- 范围：字节输入 fgetc 演示、普通文件、新打开流；C 与 POSIX 语义、glibc 2.40 / Linux v6.6 源码。macOS 实测。
- 不展开：fgetc 的 char/int 信息损失、fgets 长行、fread 元素计数、更新流切换、tail 跟踪。
- 搜索者：改为按读取结果进入处理分支。
- 学习者：EOF 是流状态，区分用户态缓冲、内核 read 返回 0 与返回负值。
- 编程者：处理错误、清理资源、说明 clearerr 不修复 I/O 原因且不移动位置。
- 求职者：空文件为何 feof 初始仍为 0，读完最后字节为何还能再进循环。

## 标题候选

- 搜索型：while (!feof(fp)) 错在哪里？
- 通俗型：文件已经读完了，为什么循环还会再进一次？
- 兼顾型：feof 为什么不能预测下一次读取？
- 选用搜索型，正文同时覆盖额外一次读取和读错误时 EOF 标志不置位的问题。
