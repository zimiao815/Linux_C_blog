# 研究记录

事实来源为 sources/ 下 POSIX.1-2024 官方页面快照：
- 第 2.5.1 节：多个句柄含流时必须协调；否则结果未定义。
- 可读、可定位且非 EOF 的流转出前须 fflush 或关闭；本例保留流，采用 fflush。
- fflush 输入扩展：把底层打开文件描述偏移设置为流位置。
- fd 读取后显式查询偏移，再 fseeko 定位流，满足显式定位后的句柄切换。
- dup 共享打开文件描述，不创建独立偏移。

只在 macOS 14.8.8 x86_64、Apple clang 16.0.0 实测，未声称 Linux 实测。
未执行不协调的 fread/read 混用，不声称固定预读 26 字节。
工程函数不用于不可定位设备、并发偏移修改或 ungetc 待处理数据。
该函数可能已经读出一个字节、但定位失败返回 -1；调用者不得自动重新读取。
fseeko 成功会清除流 EOF，read 返回 0 本身不设置流 EOF；
测试在 helper 返回 0 后再 fread，检查 feof。

真实测试覆盖：abc 连续读取、0/1/26/10000 字节逐字节交替读取、
包含全部 256 种字节值、流 EOF。
EINTR 和 EIO 仅为测试构建中的 read 替身注入，不伪装为真实设备错误。
