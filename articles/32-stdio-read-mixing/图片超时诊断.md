# 正文机制图超时诊断

本轮请求一次、重试一次，随后停止，没有调用第三次生成。
任务 ID 和时间保存在 image-jobs.json。封面首次成功，正文两次失败且均未产出 PNG。

两次收到同一 HTTP 504 响应：
upstream response header timeout after 30000 ms

有效 API 基地址：
https://codexproxy.elicc.top/backend-api/codex
路径：/images/generations

本地客户端 image_api.py 使用 urllib.request.urlopen(req, timeout=300)。
因此不是本地客户端 30 秒读超时，而是代理报告等待上游响应头超时。
同一配置下封面成功，不支持“所有请求都因认证或路径配置错误失败”的判断。

可确认：本次失败的直接触发点是代理报告的 30 秒上游响应头期限。
不能确认：是否排队、模型繁忙或上游链路故障；本地无服务端日志可区分。
进一步排查需要代理管理员按上述任务时间检查请求/上游日志和响应头等待配置。
单纯延长客户端 timeout 不会解除已返回的 HTTP 504。
