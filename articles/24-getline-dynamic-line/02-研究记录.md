# 研究记录

## 接口事实

POSIX.1-2024 声明：`ssize_t getline(char **restrict lineptr, size_t *restrict n, FILE *restrict stream)`。如果 `*lineptr` 为空，或已有对象空间不足，函数会分配或重新分配空间，并更新 `*lineptr` 与 `*n`。读取的字符包括分隔符（`getline` 的分隔符是换行符），随后追加终止空字符。

成功时返回写入对象的字节数，包含换行符，不包含终止空字符。遇到 EOF 且没有读到字节，或发生错误时返回 `-1`。`lineptr` 和 `n` 本身不能是空指针，`*lineptr` 必须是可传给 `free` 的指针。

`getline` 属于 POSIX 接口，不属于 ISO C。示例使用 `ssize_t` 保存返回值，因此包含 `<sys/types.h>`。

## 实验环境

- macOS 14.8.8 x86_64
- Apple clang 16.0.0（clang-1600.0.26.6）
- 编译：`cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`
- 未在 Linux 主机实测

## 实验结果

输入 `short\nthis-is-a-long-line-without-a-fixed-limit\nlast`：

```text
line=1 len=6 cap=8 newline=1
line=2 len=42 cap=64 newline=1
line=3 len=4 cap=64 newline=0
done lines=3 eof=1
```

补充验证：

- `ok\n`：`line=1 len=3 cap=4 newline=1`，随后 EOF。
- 空输入：没有数据行，正常到达 EOF。
- 将目录重定向到标准输入：程序返回 1，并报告 `getline: Is a directory`。
