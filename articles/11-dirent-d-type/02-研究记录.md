# 研究记录：d_type 与可靠类型判断

## 一手资料与结论

资料原文保存在 sources/，来源映射见 sources/urls.json。实现版本固定为 Linux v6.6 与 glibc-2.40。

| 技术判断 | 依据 | 核验结果 |
| --- | --- | --- |
| d_type 可能未知，应用必须处理 DT_UNKNOWN | readdir-man.html | 未知不能归为普通文件，也不表示 readdir 失败 |
| POSIX 不要求 struct dirent 有 d_type | posix-dirent.html | 2024 规范的 posix_dent 是另一种结构，不能混用要求 |
| fstatat 用 fd 作为相对路径起点 | posix-fstatat.html、stat-man.html | 避免按当前工作目录误查同名文件 |
| AT_SYMLINK_NOFOLLOW 返回最终链接自身属性 | 同上 | 与 d_type 对链接自身的分类保持一致，悬空链接也可成功 |
| glibc 批量读目录，不替未知类型逐项 stat | glibc-readdir64.c、glibc-dirstream.c | 缓冲耗尽才 __getdents64，按 d_reclen 推进 |
| 内核把文件系统提供的类型写入目录记录 | kernel-readdir.c | filldir64 写 d_type；iterate_dir 驱动目录遍历 |
| ext4 能从目录记录提供类型，但仍可返回未知 | kernel-ext4-dir.c、kernel-ext4-h.c | get_dtype 检查 filetype 特性和范围，使用映射表 |
| fd 索引指针数组，struct file 对应打开的目录 | kernel-fdtable-h.c、kernel-fs-h.c | 图中 f_inode 指向目录 inode，与子文件 inode 区分 |
| fstatat 的具体系统调用随架构和配置变化 | glibc-fstatat.c、kernel-stat.c | 图中 newfstatat 限定 x86-64 示例，不概括全部平台 |
| 查询结果不保证之后按名字操作的对象身份 | POSIX 按路径查询语义；受控删除实验 | 目录 fd 固定起点，不锁定子项；不宣称补查消除 TOCTOU |

## 实测记录

2026-10-02 重新执行 `python3 verify.py`，14 项记录全部符合预期，包括两次严格编译。编译参数为 `-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`，无警告。

环境是 macOS 14.8.8 / Darwin 23.6.0 x86_64，Apple clang 16.0.0。机器无可用 docker、podman 或 colima；未声称 Linux 实测。原始 stdout、stderr、退出状态与环境见 verification.json，便于阅读的副本见 actual-output.txt。

- 正常目录：六项均由 d_type 分类，退出 0。
- 强制未知：六项均由 fstatat 分类，类型与正常组一致，退出 0。
- 空目录：无输出，退出 0。
- 不存在的目录、普通文件当目录、错误参数：退出 1。
- 注入首次补查 EINTR：重试成功，输出六项，退出 0。
- 注入 note.txt 查询 EACCES：该项报错，其他五项输出，退出 1。
- 注入 readdir EIO、dirfd EBADF：报告错误，退出 1。
- 包装 closedir，在实际关闭后模拟 EIO：报告关闭错误，退出 1。
- 在补查 note.txt 前实际 unlinkat 删除文件：查询 ENOENT，其他五项输出，退出 1。
- 所有六条注入用例都确认关闭出口被调用一次。未使用无效 DIR 指针制造故障。

## 实验边界

`--unknown` 在应用中替换本次采用的类型值，不修改目录记录或文件系统。没有实测自然返回 DT_UNKNOWN 的文件系统，也没有性能基准。权限错误通过包装注入，未声称完成真实权限环境实验。设备类型分支未创建字符或块设备验证；输出失败检查经代码审阅，未注入 printf / fflush 失败。不承诺穷尽全部系统故障。
