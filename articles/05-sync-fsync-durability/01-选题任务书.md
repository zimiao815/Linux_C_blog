# `sync`/`fsync`/`fdatasync` 与落盘

- 核心问题：`write` 返回成功，是否等于数据已经安全落到磁盘？什么时候需要 `fsync`？
- 一句话结论：`write` 成功通常只表示数据已被内核接收，不等于已经持久化到稳定存储；`fsync(fd)` 要求该文件的数据及恢复数据所需的元数据写入稳定存储，`fdatasync(fd)` 只要求数据及必要元数据，`sync()` 则是全局请求回写，不能替代关键文件的逐个确认。
- 适用范围：POSIX/Linux 文件描述符语义；实验在 macOS 14.8.8、Apple clang 16 上验证。具体硬件、文件系统和挂载选项会影响落盘时机。
- 不处理：数据库 WAL 设计、磁盘缓存断电保护、`O_DIRECT`、远程文件系统一致性和 ext4 特定挂载选项。
