## 实验

- 实际平台：macOS 14.8.8 x86_64，Apple clang 16.0.0；没有 Linux 运行环境，正文已明示。
- 主程序：setvbuf_probe.c；独立非法模式探针：invalid_mode.c。
- 复现：`/Users/zhaodan/.workbuddy/binaries/python/envs/default/bin/python verify.py`（在文章目录运行）。脚本复制 C 文件到新临时目录，严格编译后逐个启动新进程，结束删除临时二进制与数据文件。
- 编译参数：`-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。两文件均无警告。
- 12 组成功实验：文件 / 管道 × full / line / none × newline / partial；stdin 用独立管道门控，stderr 检查点确认写入调用已返回。
- 结果：文件、管道一致；full 的两种文本均暂存；line 只提交带换行文本；none 两种文本均提交。放行并 fclose 后所有文本完整，退出 0。
- 6 组异常或拒绝路径：stdin EOF、未知模式、缺少参数、文件大小限制下 full 关闭报错、同一限制下 none 写入报错、独立探针确认 setvbuf 拒绝非法模式。
- RLIMIT_FSIZE/SIGXFSZ 的修改仅在被测子进程中执行，不修改工作环境的限制和信号配置。
- 独立探针拒绝非法模式是预期成功，所以探针自身退出 0；主程序五种失败场景均退出 1。
- 真实输出和状态：actual-output.txt / verification.json。正文观察表由 JSON 生成，并校验文件与管道结果一致。
- 本文未运行悬空数组等未定义行为，不声称复现崩溃。标准约束与源码解释支持生命周期结论。
- 边界：小量字节输出、单线程、阻塞；不测系统调用次数、精确容量、吞吐、磁盘持久化、非阻塞重试。
