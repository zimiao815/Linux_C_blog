# 标准 I/O 库第 4 篇：setvbuf 与缓冲配置

- 规划对应：标准 I/O 库序号 4；前置序号 3，标准输出的缓冲。
- 核心问题：如何给标准 I/O 流设置合适的缓冲方式，并保证自备缓冲区有效？
- 直接结论：在流上做其他操作之前配置并检查结果；根据输出需求选择模式；自备缓冲区的有效期必须覆盖流的使用期。
- 范围：单线程、阻塞、字节输出；三种模式、时机、大小、存储所有权。
- 不展开：fflush 到内核后的持久化边界、非阻塞恢复协议、fork、宽字符流、吞吐基准测试。
- 搜索者：用一个可运行程序对比三种模式。
- 学习者：看懂 FILE 的模式标志、缓冲指针和 fd 的不同职责。
- 编程者：把配置放在初始化阶段，保证所有清理分支中流先于自备数组结束使用。
- 求职者：解释为什么自动数组可能留下悬空指针，为什么 static 不是唯一安全选择。

## 标题选择

- 搜索型：setvbuf 的三种缓冲方式、设置时机与缓冲区生命周期
- 通俗型：把数组交给输出流，函数返回以后怎么办？
- 兼顾型（选用）：setvbuf 怎么设置缓冲，才不会留下悬空指针？
- 理由：保留检索接口名，用实际的资源生命周期约束连接模式配置与工程错误；正文不虚构崩溃实测。
