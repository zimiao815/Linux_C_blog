# 研究记录：opendir / readdir

## 事实与依据

来源正文已下载到 sources/，URL 对应关系在 sources/urls.json。实现源码固定为 glibc-2.40 与 Linux v6.6，避免引用随主分支漂移。

| 技术判断 | 直接来源 | 核验结果 |
| --- | --- | --- |
| readdir 在结束和失败时均返回 NULL，结束不修改 errno | POSIX.1-2024 readdir；Linux readdir(3) | 一致；调用前清零，NULL 后立即判断 |
| 成功记录的存储可能被同一流后续读取覆盖，不可 free | POSIX readdir；Linux readdir(3) | 需要保留名字时自行复制 |
| 增删目录项的可见性不保证；结果不自动排序 | POSIX readdir；Linux readdir(3) | 不能描述为目录快照 |
| 同一个目录流的并发读取需要外部同步 | POSIX.1-2024 readdir；Linux readdir(3) | 同步范围应含读取后消费或复制 |
| opendir 打开目录并分配 DIR 缓冲，保存 fd、offset、size、data | glibc opendir.c、dirstream.h | 私有布局不作为应用 ABI 使用 |
| readdir64 缓冲耗尽才调用 __getdents64，随后按 d_reclen 移动缓冲 offset | glibc readdir64.c | 可解释“一次返回一项，内核一次给一批” |
| getdents64 通过 fd 获取 file，iterate_dir 用 f_pos 初始化 ctx.pos 并调用 iterate_shared | Linux fs/readdir.c | 内核位置和用户缓冲位置不同 |
| file.f_path 是内嵌 struct path；path 包含 mnt 与 dentry；dentry 含 d_inode | Linux fs.h、path.h、dcache.h | 对象关系图用展开结构表现包含关系 |
| 进程 fd 表中的 fd 数组存储 struct file 指针 | Linux fdtable.h | fd 是索引，不能画成直接指向 struct path |
| closedir 释放目录流并关闭其 fd | closedir(3)；glibc closedir.c | 不再单独 close(dirfd(dir)) |

## 可重复实验

- 主程序：list_dir.c。严格编译参数：`-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。
- 环境：macOS 14.8.8 / Darwin 23.6.0 x86_64；Apple clang 16.0.0。
- 执行：`python3 verify.py`。脚本在新的临时目录创建样本、编译、执行并清理，stdout、stderr、退出状态保存在 verification.json。
- 正常目录包含 a.txt、.hidden、subdir、link。实际顺序为 .hidden、subdir、link、a.txt；退出 0。顺序不属于接口保证。
- 空目录：不输出名字，退出 0。
- missing：opendir 返回 ENOENT，对应本机文本 No such file or directory，退出 1。
- sample/a.txt：opendir 返回 ENOTDIR，对应本机文本 Not a directory，退出 1。
- readdir 故障注入：返回第一条非点记录后，下一次以 NULL/EIO 模拟失败。打印一条记录，再输出 Input/output error，退出 1。
- 旧 errno 注入：成功返回有效记录时设置 EACCES，下一轮主程序重新清零。遍历仍正确结束，退出 0。这是测试包装行为，不是声称本机 readdir 会这样设置 errno。
- 故障注入通过临时副本替换调用名实现；生产示例没有测试开关。不关闭正在使用的目录 fd，不使用无效 DIR 指针制造未定义行为。
- 首次以宏替换头文件声明时遇到 macOS `$INODE64` 符号重命名问题；改为头文件处理完后仅替换调用点，严格编译及两条注入路径通过。

## 实现边界

- 本机无现成 Linux 容器运行时，未作 Linux 实测或 strace；第二章只声称固定源码核验。
- glibc readdir64.c 会将某些文件系统目录已删除时的 ENOENT 转换为正常结束。正文用“需要上报的错误”，不声称每个 getdents64 负返回都必然原样上报。
- POSIX.1-2024 对不同目录流的线程要求已更新；旧 man-page 中引用较早 POSIX 的解释不用于概括最新规范。
- 没有模拟 closedir、内存分配和 stdout 刷新失败；代码检查相关返回值，不声称穷尽所有环境故障。
- 目录项记录不是子文件内容，也不是内核 dentry；读取名字不会自动打开每个子文件。
