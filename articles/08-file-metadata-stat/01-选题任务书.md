# 文件元数据与 `stat`

- 核心问题：程序只拿到一个路径时，怎样读取文件类型、大小、inode、权限和时间等元数据？
- 一句话结论：调用 `stat(path, &st)`，成功后从 `struct stat` 读取元数据；`st_mode` 用 `S_ISREG` 等宏判断类型，`st_size` 表示文件大小，`st_ino` 是文件在所属文件系统内的 inode 编号。`stat` 成功只说明这次查询拿到了一个快照，不代表后续操作仍然安全或对象不会变化。
- 适用条件 / 范围：POSIX `stat` 与 Linux `stat(2)` 的常见字段和错误处理；示例在 macOS 上用严格编译选项验证，Linux 结构和调用语义基本一致。目录遍历、`stat`/`lstat` 差异、权限位细节和安全路径操作留给后续篇目。
- 不处理：符号链接跟随规则（第 2 篇）、`opendir`/`readdir` 目录遍历（第 3 篇）、`d_type` 可靠性（第 4 篇）、权限位与 `umask`（第 9、10 篇），也不把 `stat` 当成 TOCTOU 安全检查。
- 四类读者视角（各一句话）：
  - 搜索者：用一段短代码打印路径对应的类型、大小和 inode，并知道失败时看什么。
  - 学习者：理解路径名、目录项、inode 与 `struct stat` 返回值之间的关系。
  - 编程者：知道如何检查返回值、解释时间字段、处理目录大小和查询后的竞态。
  - 求职者（按需）：能说清 `stat`、`fstat` 的对象来源，以及 `st_mode` 为什么同时包含类型和权限位。
