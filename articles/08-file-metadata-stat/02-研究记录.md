# 研究记录（文件与目录·第 1 篇：文件元数据与 `stat`）

## 核心判断

`stat()` 根据路径查询目标对象的状态，把结果写入调用者提供的 `struct stat`。`st_mode` 同时携带文件类型和权限位，类型应使用 `S_ISREG`、`S_ISDIR` 等宏判断；`st_size`、`st_ino`、`st_nlink` 和时间字段分别表达大小、所属文件系统内的 inode 编号、硬链接数和时间信息。调用返回 0 表示查询成功，返回 -1 时才读取 `errno`。

`stat` 返回的是调用时的元数据快照。Linux man-pages 明确提醒，不同字段可能来自执行期间的不同时间点，因此不能把一次 `stat` 当作后续 `open`、`unlink` 或读写操作的安全授权。

## 关键事实清单

1. 头文件是 `<sys/stat.h>`，原型为 `int stat(const char *path, struct stat *buf)`。
2. 只有返回值为 -1 时才读取 `errno`；常见错误包括路径不存在（`ENOENT`）、路径前缀没有搜索权限（`EACCES`）和路径组件不是目录（`ENOTDIR`）。
3. `st_mode` 的类型部分不能直接和一个魔数比较，应使用 `S_ISREG(st_mode)`、`S_ISDIR(st_mode)` 等宏。
4. `st_ino` 与 `st_dev` 组合后才可在多文件系统环境中定位对象；单独的 inode 数字可能在不同挂载点重复。
5. `stat` 查询路径，`fstat` 查询已经打开的文件描述符；本篇只用 `stat`，不展开 `lstat` 的符号链接差异。
6. `st_atime`、`st_mtime`、`st_ctime` 的更新受访问方式和文件系统挂载选项影响，不能把它们都解释成“创建时间”。

## 实验记录

环境：macOS Darwin 23.6.0，Apple clang 16.0.0。

编译选项：`cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。

代码：`stat_demo.c`。程序创建一个内容为 `hello\n` 的普通文件和一个目录，分别调用 `stat`，打印类型、大小、inode、硬链接数和权限位，最后删除临时对象。写入循环处理短写与 `EINTR`，所有创建、查询、关闭和清理操作都检查返回值。

运行命令：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g stat_demo.c -o stat_demo
./stat_demo
```

实际输出：

```text
stat_demo_file.tmp: type=regular size=6 inode=65986394 nlink=1 mode=0640
stat_demo_dir.tmp: type=directory size=64 inode=65986395 nlink=2 mode=0750
```

inode 编号和目录的 `st_size` 会随文件系统及运行时变化；本次输出要观察的稳定事实是：普通文件类型为 `regular`、内容 6 字节、初始硬链接数为 1；新目录类型为 `directory`，权限位来自 `mkdir` 的请求模式（还会受 `umask` 影响），目录大小不是“里面有几个文件”。

## 矛盾与处理

- macOS 与 Linux 的 `struct stat` 字段类型、时间字段命名和目录内部布局存在实现差异。正文只依赖 POSIX 共有字段与 Linux man-pages 的通用语义，不把字节布局或目录大小数值写成跨平台保证。
- `st_ctime` 在不同系统上的解释可能不同。正文按 Linux 语境称为 inode 状态改变时间，并提醒不要把它当作创建时间；如果要讨论创建时间，需使用平台特定接口（Linux 可另看 `statx`）。
