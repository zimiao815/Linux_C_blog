# 研究记录

研究日期：2026-10-11。关键来源原文保存在 `sources/`，地址见 `sources/urls.json`。

## 事实与证据

| 判断 | 一手资料 | 支撑范围 |
| --- | --- | --- |
| fopen 返回控制流的对象指针，失败为空指针 | POSIX fopen：DESCRIPTION、RETURN VALUE | 公开语义；POSIX 增补 errno 和底层 fd 规则 |
| 初始 EOF、错误标志被清除 | POSIX fopen：DESCRIPTION | 直接规定 |
| FILE 内部布局不是可移植接口 | POSIX stdio.h；glibc struct_FILE.h 的接口警告 | POSIX 允许不完整类型；glibc 展示特定实现字段 |
| fileno 返回关联 fd，失败为 -1 | POSIX fileno | 已有描述符的查询，不是复制操作 |
| fgetc 返回 unsigned char 转 int；EOF 与读取错误需分辨 | POSIX fgetc：DESCRIPTION、RETURN VALUE | EOF 标志、错误标志与 POSIX errno 规则 |
| fclose 处理缓冲、关闭 fd，返回后流不可再用 | POSIX fclose | 包括失败后也不能再次使用流；不把重试系统调用规则套到 fclose |
| glibc FILE 含缓冲指针、_fileno 和 _flags | glibc-2.40/libio/bits/types/struct_FILE.h | glibc 实现，不推广到 macOS 或所有 C 库 |
| 创建对象、打开底层文件、关联 fd、失败清理 | glibc-2.40/libio/iofopen.c 的 __fopen_internal；fileops.c 的 _IO_file_open | 普通文件路径 |
| 读缓冲命中可直接取字节；补充读取返回 0 时设置 EOF | struct_FILE.h 的 __getc_unlocked_body；fileops.c 的 _IO_new_file_underflow | 源码证据；不是本机系统调用跟踪结果 |
| fdtable 的 fd 数组保存 struct file 指针 | Linux v6.6/include/linux/fdtable.h | fd 为索引；files_struct.fdt 指向 fdtable |
| struct file 保存 f_pos 与 f_inode | Linux v6.6/include/linux/fs.h | 内核打开文件对象及关联 inode |
| 内存流构成没有 fd 的例外 | POSIX fmemopen、fileno；Linux fmemopen(3) 手册 NOTES（原文已保存） | 公开接口用途与实现边界，正文不展开内存流用法 |

## 实验

源文件：`stream_identity.c`。验证脚本：`verify.py`。在临时干净目录复制源文件后编译运行，目录退出时删除。`verification.json` 保存环境、编译参数、stdout、stderr 和退出状态，`actual-output.txt` 是可读版本。

环境：macOS 14.8.8、Darwin 23.6.0、x86_64；Apple clang 16.0.0。

编译参数：`-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`，零警告。

验证案例：

1. 单字节 A：初始两个标志为 0，第一读返回 65，第二读遇到 EOF，错误标志仍为 0。
2. 空文件：第一次读取即 EOF，无错误标志。
3. 不存在路径：fopen 失败，退出状态 1。
4. 缺少参数：用法提示，退出状态 1。
5. 输入目录：本机 fopen 成功，第一次 fgetc 失败，报告 Is a directory 并关闭流。
6. stdout 指向只读打开的文件：最终 fflush 失败，报告 Bad file descriptor，退出状态 1。

案例 6 由验证器传入只读文件描述符作为 stdout，不修改输入文件。未通过关闭流的底层 fd 来注入错误，避免不合法的生命周期操作。

## 边界与未实测项

- 没有可用 Linux 运行环境。公开 POSIX 行为在 macOS 实测；Linux/glibc 内部关系从指定版本源码核验。不得把 macOS 地址、fd 数值、错误时机或内部结构当作 Linux 测量结果。
- 没有用 strace 测量调用次数，不声称一次具体 fgetc 对应多少次 read。
- 未注入 fileno 失败、输入流 fclose 失败、信号中断、内存耗尽、多线程或非阻塞恢复；这些分支采用返回值检查与退出策略，不声称全部错误都已覆盖。
- 没有把关闭后对象再访问或双重关闭作为实验。
- 不将 FILE 内部字段用于示例，未复制或手动释放 FILE。
