## 事实与证据

| 事实 | 一手依据 | 适用范围与限制 |
| --- | --- | --- |
| 输出刷新提交流中未写出的数据，成功 0、失败 EOF；POSIX 设置 errno | POSIX.1-2024 fflush DESCRIPTION / RETURN VALUE | 对输出流及最近操作不是输入的更新流；本文只使用输出流 |
| 刷新失败可能有 EFBIG、EINTR、EAGAIN、EPIPE；后者还发 SIGPIPE | POSIX fflush ERRORS | 本次只实测文件大小限制导致 EFBIG；其他由规范支撑 |
| 流刷新和内核缓存同步是不同接口 | Linux fflush(3) NOTES，fsync(2) DESCRIPTION；POSIX fsync | macOS 实验不作为 Linux 持久化实测 |
| glibc 调用 _IO_SYNC 分派，普通流检查待输出区域并写出，没有自动 fsync | glibc 2.40 iofflush.c，fileops.c 的 _IO_new_file_sync / new_do_write / _IO_new_file_write | 普通文件输出路径，非所有 FILE 后端；省略中间宏与分派细节 |
| _IO_write_base / _IO_write_ptr 是待写区域边界；成功写出路径复位指针 | glibc struct_FILE.h / fileops.c | 复位不代表擦除原内存内容；空待写区可以直接成功 |
| fd 查表关联 struct file，其 f_inode / f_mapping 指向 inode / address_space | Linux v6.6 fdtable.h / fs.h | 普通文件结构示意，省略引用计数和锁，非本机内存快照 |
| 普通缓冲写的可见性不足以证明断电持久化 | Linux write(2) NOTES，fsync(2)；文件观察实验 | 不扩展到 O_DIRECT、特殊文件系统或完整故障恢复保证 |
| fsync 不刷新 FILE 缓冲；必须在刷新后执行 | 两个接口作用对象 + sync-only 实测 | 无并发写入场景；fsync 成功不等于对尚未交给内核的字节作出承诺 |
| 文件 fsync 不一定保证目录项已持久化 | Linux fsync(2) DESCRIPTION，POSIX fsync APPLICATION USAGE | 新建或改名需按协议同步相关目录；本文不实现原子替换 |
| 关闭流会尝试刷新，失败也不能再次使用该流 | POSIX fclose | 程序所有已配置流路径统一 fclose；关闭不提供回滚 |
| 自动刷新条件、fflush(NULL) 的输出刷新范围 | glibc 2.40 Flushing Buffers | 等待输入使用 read 而非 stdio 输入，避免实验干扰 |
| ISO C 对输入流 fflush 不提供通用清输入行为；POSIX 有可定位输入扩展 | POSIX fflush 对 ISO C 额外段落的 CX 标记，Linux fflush(3) | 不把它用于键盘输入清理；未执行未定义行为探测 |

## 实验复现

```sh
/Users/zhaodan/.workbuddy/binaries/python/envs/default/bin/python linux_c_blog/articles/19-fflush-boundaries/verify.py
```

- 实际环境：macOS 14.8.8 x86_64；Apple clang 16.0.0。
- 编译：`-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`，无警告。
- 验证器在全新临时目录构建与运行；程序和子进程有超时，临时目录自动清理。
- 数据固定为 `record=42\n`，9 字节；setvbuf 在 stdout 任何其他操作前配置，缓冲数组是 static 存储期。
- stdout 重定向为普通文件：buffered / flush / sync-only / flush-sync，共 4 组。stderr 观察点确认控制流已通过要求的调用，再由父进程读取文件。前两种有无刷新的区别，以及 fsync 单独调用不能刷新 stdio 的结果，均记录在 verification.json。
- stdout 为管道：buffered / flush，共 2 组。观察点前父进程从不读取 stdout；select 只测可读性。此刻子进程仍在 read 等待，不能是关闭流或退出造成的可读。最后放行并收集全部数据，退出 0。
- 失败与拒绝：缺参数、未知模式、stdin EOF、管道 fsync、文件大小上限 0，共 5 组。退出均为 1。
- 文件大小限额仅作用于测试子进程，SIGXFSZ 在子进程忽略以观察返回值；不改父进程限制。fputs 成功，fflush 和 fclose 均报 File too large，文件 0 字节。
- 管道 fsync 本机报告 Operation not supported；没有把它写成 Linux 应报告的错误文本。
- 观察必须在放行前：所有成功组关闭后最终文件/管道内容相同，不能靠进程退出后的 cat 判断 fflush 差别。
- errno 只在失败后使用；fsync/read 对 EINTR 重试。fflush 失败直接向上传递，不假设库保存全部未写字节，也不盲目重发。
- 本文示例拥有 stdout 的最终使用权，关闭后没有再使用它的退出处理函数。不能照搬到仍有后续 stdout 使用者的代码中。
