# 编译与复现

正文片段均来自同目录的 `fork_demo.c`，不是各自独立的完整程序。程序需要 `errno.h`、`stdio.h`、`stdlib.h`、`sys/types.h`、`sys/wait.h`、`unistd.h`，并在头文件之前定义 `_POSIX_C_SOURCE 200809L`。

在本目录执行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow \
   -O0 -g fork_demo.c -o /tmp/fork-demo
/tmp/fork-demo
python3 verify.py
```

正文样例输出保存在 `sample-output.txt`，全部运行记录在 `actual-output.txt` 和 `verification.json`。重新运行 `verify.py` 会更新证据，PID 会变化；若更新正文样例，必须使用新记录中的原始输出。

实验平台是 macOS 14.8.8 x86_64，Apple clang 16.0.0，未在 Linux 主机实测。示例使用 POSIX 接口，Linux 上的接口语义另由 POSIX.1-2024 和 Linux man-pages 核对，不以 macOS 运行结果代替 Linux 实测。

## 验证范围

- 正常创建：20 次运行检查创建前一行、创建后两行，确认父进程身份保留、父进程返回值等于子进程 PID、子进程返回 0；不限定父子输出顺序。
- 普通文件重定向：检查无缓冲设置后的三行结果，不仅测试管道捕获。
- 创建失败：通过 `fault_injection.c` 的测试替身返回 `EAGAIN`，确认程序报告错误并返回失败，没有执行创建后的输出。
- 等待中断：测试替身让第一次 `waitpid` 返回 `EINTR`，第二次执行真实等待，确认成功回收。
- 等待失败：直接测试 `wait_child` 的 `ECHILD` 传递，不创建遗留的子进程。
- 输出失败：将 stdout 接到只读描述符，确认创建前打印失败即结束。

故障注入只验证应用分支，不能证明真实系统资源上限或信号送达时序。多次运行也不能证明调度顺序的保证。示例中没有安装信号处理器、改变子进程回收方式或启用其他线程；不适用于其他代码同时抢先回收该子进程的情形。
