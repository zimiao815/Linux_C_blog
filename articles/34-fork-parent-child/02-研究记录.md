## 核心事实与依据

| 判断 | 直接依据 | 边界 |
| --- | --- | --- |
| 成功后父子都从调用返回处继续执行 | POSIX `fork`，RETURN VALUE：Both processes shall continue to execute from the fork() function | 不表示从 `main` 重新执行，也不能机械限定为源代码下一行 |
| 父进程得到子进程 PID，子进程得到 0 | POSIX `fork` 与 Linux `fork(2)` 的返回值章节 | 子进程返回的 0 不等于子进程自己的 PID |
| 失败返回 -1，不创建子进程，并设置错误号 | 同上 | 故障注入验证应用处理，不代表实测资源耗尽 |
| 父子可以独立执行 | POSIX `fork`，DESCRIPTION：both ... capable of executing independently | 输出顺序是运行观察，不能提升为调度保证 |
| 子进程有自己的 PID | POSIX `fork` 的首条差异、Linux `fork(2)` DESCRIPTION | 父进程继续保留原身份 |
| `waitpid` 等待指定子进程，遇到 `EINTR` 可能失败返回 | POSIX `waitpid` DESCRIPTION、RETURN VALUE、ERRORS | 本例默认信号处置，无其他回收者，无调试器控制 |
| 先判断正常退出，再读退出码 | POSIX `waitpid`，`WIFEXITED`、`WEXITSTATUS` | `status` 是编码后的等待状态 |
| `_exit` 不刷新标准 I/O 流 | POSIX `_exit`：Open streams shall not be flushed | 本例在任何 stdout 操作前设为无缓冲，不能照搬到缓冲输出 |
| `fork` 后的两个流句柄需要满足协调规则，无缓冲流不需额外动作 | POSIX 2.5.1：If it is a stream which is unbuffered, no action need be taken | 无缓冲不提供多进程整行打印的原子性保证 |
| Linux `fork` 可能因进程上限返回 `EAGAIN`，内存不足返回 `ENOMEM` | Linux `fork(2)` ERRORS | 正文只列例子，不把它们当作所有平台的完整错误清单 |
| 多线程进程 fork 后的子进程受异步信号安全限制 | POSIX `fork` DESCRIPTION 与 Linux `fork(2)` | 本文打印示例严格限定单线程，不宣称 `printf` 可用于多线程 fork 后的子进程 |

## 实验与观察

- 系统：macOS 14.8.8 x86_64；编译器：Apple clang 16.0.0。
- 两个 C 文件均按 C17 与 `-Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g` 编译，无警告。
- 主实验运行 20 次，均成功退出；每次创建前一行、创建后两行，父进程返回值与子进程 PID 一致，子进程返回 0。
- 这 20 次均观察到父进程先输出。未伪造子进程先输出的样例，也未把观察写成调度承诺。
- 普通文件重定向检查通过。
- 创建前 stdout 接只读描述符，打印失败，程序返回失败。
- API 替身注入 `EAGAIN`：没有创建后的输出，程序返回失败。
- API 替身注入一次 `EINTR`：等待函数重试后调用真实 `waitpid` 并成功回收。
- API 替身注入 `ECHILD`：直接测试帮助函数，不创建子进程，验证错误被传递而没有无限重试。
- 完整命令、真实输出和退出状态见 `verification.json`、`actual-output.txt`，正文样例与 `sample-output.txt` 一致。

## 资料与环境限制

本机没有发现可用的 Docker、Podman、Colima、Lima、OrbStack 或 QEMU 工具。没有 Linux 执行证据，未把 macOS 结果称为 Linux 实测。这里使用的是两平台共有的 POSIX 接口语义；Linux 侧以官方接口手册核对，内核调用链、写时复制和文件对象继承未在本篇展开。

POSIX 规范和 Linux 手册对本篇核心返回值语义没有冲突。规范中多线程、资源继承的细节比本文范围更广，正文只保留会影响示例适用性的限制。
