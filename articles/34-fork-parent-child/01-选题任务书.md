# fork 之后，父子进程从哪里继续执行？

- 系列：进程基础与进程控制，第 1 期；产物目录编号 34。
- 核心问题：一次成功的 `fork` 调用后，父子进程各自从哪里继续执行？
- 一句话结论：父子进程都从 `fork` 调用返回处继续执行，父进程获得子进程 PID，子进程获得 0；失败时原进程获得 -1，没有创建子进程。
- 适用条件：POSIX 接口，单线程示例；未设置自动回收子进程的信号处置，没有其他代码抢先回收同一子进程。演示普通运行，不涉及调试器控制的停止状态。
- 实验平台：macOS 14.8.8 x86_64、Apple clang 16.0.0。无 Linux 主机实测；Linux 语义由 POSIX 和 Linux man-pages 交叉核对。
- 不处理：写时复制细节、文件偏移共享、缓冲重复输出、完整的退出状态解码、线程与信号处理。
- 搜索者：立即分清父子返回值，知道后续代码在哪个进程执行。
- 学习者：理解相同代码如何由两个进程沿各自执行路径继续运行。
- 编程者：检查失败分支，结束子进程路径，由父进程负责回收。
- 求职者：解释一次调用后两个进程返回，以及父子运行顺序为何不能保证。
- 实验：显示创建前的 PID 和创建后各进程的 PID、返回值；检查 20 次运行及文件重定向。使用明确标注的 API 替身验证创建失败、等待中断与等待失败，不通过耗尽系统资源制造故障。
- 配图：AI 生成独立封面、成功与失败的执行分支图；本期不展开内核调用路径。
