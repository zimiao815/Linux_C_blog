# 研究记录

资料快照位于 sources/，主依据为 POSIX.1-2024：
- fmemopen：关联固定容量缓冲区；传入调用者数组与传入 NULL 的所有权不同。
- open_memstream：动态分配，顺序追加时长度不含终止空字符；
  成功 fflush/fclose 更新 bufp 与 sizep。刷新后的结果只保证到下一次写入或 fclose 前有效。
- 随机定位时 sizep 是当前位置和缓冲内容长度二者较小者，正文不推广顺序写入结论。
- Linux man-pages：内存流不关联底层 fd；固定容量错误可能延后到刷新/关闭。

工程适配主动把 n >= cap 判为 ENOSPC，确保成功结果为完整 C 字符串。
不声称所有 libc 容量不足都产生 ENOSPC。
stdio 返回的字符数对本文 ASCII 文本等于字节数；边界测试另外覆盖嵌入空字符。

实验环境：macOS 14.8.8 x86_64，Apple clang 16.0.0。未在 Linux 主机实测。
动态示例是进程级实验：若最终 fclose 失败，直接返回退出，
不再使用未保证更新的指针和长度；不是通用分配器故障恢复函数。

测试范围：
固定缓冲容量 16/9/8/4/0，验证成功、拒绝和边界外哨兵未被改写。
动态写入 0/8/20000 字节，包含全部字节值；刷新后逐字节检查，
再追加 X 并关闭，检查最终长度和终止符。未模拟系统内存耗尽。

## 2026-11-04 用法改写

正文改用两个独立 hello 程序，不再展示 report_to_memory 适配器。固定示例显式检查 n >= sizeof buf；动态示例先成功关闭，再读取 text/len 并释放。
参数、只写流、成功返回 FILE * / 失败 NULL、结果有效期与释放规则继续依据已保存的 POSIX 原文。原有边界测试保留作补充证据，新示例单独编译运行。
