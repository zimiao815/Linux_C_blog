# 研究记录

## 接口事实

C17 `fwrite` 声明为 `size_t fwrite(const void * restrict ptr, size_t size, size_t nmemb, FILE * restrict stream)`。函数最多写入 `nmemb` 个元素，每个元素 `size` 字节，返回成功写入的元素数。

返回值小于 `nmemb` 时，C17 规定是写错误；如果 `size` 或 `nmemb` 为 0，返回 0 且流状态不变。POSIX 说明写错误会设置流错误指示器，并设置 `errno`。

成功调用 `fwrite` 不等于数据已经完成最终刷新。`fflush` 和 `fclose` 都可能报告后续刷新错误；`fflush` 也不等同于物理存储持久化。

## 实验环境

- macOS 14.8.8 x86_64
- Apple clang 16.0.0（clang-1600.0.26.6）
- 编译：`cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`
- 未在 Linux 主机实测

## 实验结果

临时文件写入 3 个 4 字节元素，再对只读流执行同样写入：

```text
normal returned=3 requested=3 bytes=12 flush=0 pos=12 error=0
readonly returned=0 requested=3 error=1
```

第一轮完整写入并刷新成功。第二轮返回 0，并设置错误指示器。
