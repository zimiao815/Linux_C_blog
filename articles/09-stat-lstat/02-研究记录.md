# 研究记录（文件与目录·第 2 篇：`stat` 与 `lstat`）

## 核心判断

`stat()` 和 `lstat()` 都把文件状态写入 `struct stat`，区别只在最后一个路径分量是符号链接时的处理方式：`stat()` 继续解析链接文本并报告目标对象；`lstat()` 停在链接自身并报告 `S_IFLNK`。因此，目标被删除后，悬空链接仍可被 `lstat()` 发现，而 `stat()` 会因无法解析目标而失败。

## 材料卡片

## 关键事实清单

1. 头文件是 `<sys/stat.h>`，两个接口都返回 `0` 表示成功，返回 `-1` 表示失败。
2. `stat()` 默认跟随符号链接；`lstat()` 只对最后一个路径分量不跟随。
3. 对链接自身，`S_ISLNK(st.st_mode)` 应为真；`st_size` 是目标路径文本长度，不是目标文件大小。
4. 删除目标文件不会删除链接目录项。此时 `stat(link, &st)` 常见错误是 `ENOENT`，`lstat(link, &st)` 仍能返回链接元数据。
5. 符号链接目标使用相对路径时，路径是相对于链接所在目录解释的，不是相对于调用进程的当前工作目录。
6. 如果只想检查链接而不跟随它，可用 `lstat()`；`fstatat()` 也能通过 `AT_SYMLINK_NOFOLLOW` 表达同样意图。二者都不能单独消除检查与使用之间的竞态。

## 实验记录

环境：macOS Darwin 23.6.0，Apple clang 16.0.0。

编译选项：`cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`。

代码：`stat_lstat_demo.c`。程序创建一个 12 字节普通文件和一个指向它的相对符号链接，分别调用 `stat()` 与 `lstat()`；随后删除目标文件，再次查询悬空链接。所有创建、写入、关闭、删除和清理操作都检查返回值。

运行命令：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g stat_lstat_demo.c -o stat_lstat_demo
./stat_lstat_demo
```

实际输出：

```text
target via stat: type=regular size=12 inode=65990073
link via stat: type=regular size=12 inode=65990073
link via lstat: type=symlink size=21 inode=65990074
broken link via stat: stat errno=2 (No such file or directory)
broken link via lstat: type=symlink size=21 inode=65990074
```

inode 编号和具体错误文本可能随系统变化；稳定事实是：`stat` 看见目标，`lstat` 看见链接，目标删除后只有 `lstat` 还能读取链接自身。`st_size=21` 来自链接文本 `stat_lstat_target.tmp` 的长度。

## 矛盾与处理

- POSIX 与 Linux man-pages 对基本跟随规则一致。Linux 还提供 `fstatat(..., AT_SYMLINK_NOFOLLOW)` 和 `openat2()` 等扩展，正文只把前者作为接口对照，不把 Linux 专属能力写成可移植保证。
- 符号链接 `st_mode` 的权限位在 POSIX 中没有普通文件权限的稳定语义，正文只使用 `S_ISLNK` 判断类型。
- 示例在 macOS 上运行，具体 inode 数字、错误编号对应的文本和文件系统行为可能不同；文章依赖的是 POSIX 接口语义和可重复观察到的类型/大小关系。
