# `stat` 与 `lstat`

- 核心问题：为什么查看符号链接时，`stat` 和 `lstat` 得到的结果不同？
- 一句话结论：`stat(path, &st)` 默认跟随最后一个路径分量的符号链接并返回目标对象的状态；`lstat(path, &st)` 不跟随最后一个符号链接，返回链接自身的状态。目标不存在时，`stat` 通常失败，而 `lstat` 仍可识别悬空链接。
- 适用条件 / 范围：POSIX `stat`、`lstat` 与 Linux `stat(2)` 的路径解析语义；示例在 macOS 上用严格编译选项验证，代码只使用 POSIX 常见接口。`fstatat` 的 `AT_SYMLINK_NOFOLLOW`、`openat2` 和更完整的安全打开策略留给后续篇目。
- 不处理：目录遍历与 `readdir`（第 3 篇）、`d_type` 可靠性（第 4 篇）、符号链接创建和读取接口的完整介绍（第 8 篇）、TOCTOU 防护的系统化方案（第 12 篇）。
- 四类读者视角（各一句话）：
  - 搜索者：马上知道检查链接目标该用 `stat`，检查链接自身该用 `lstat`。
  - 学习者：理解路径解析在最后一个分量处如何决定跟随或停止。
  - 编程者：能处理悬空链接、返回值和 `errno`，不把一次查询当成安全授权。
  - 求职者（按需）：能说清 `stat`、`lstat`、`fstatat(..., AT_SYMLINK_NOFOLLOW)` 的区别。
