# snprintf 返回 11，为什么只剩 7 个字符？

`snprintf` 最容易让人困惑的地方，是返回值和缓冲区里的实际字符串可能不一样。

```c
char buf[8];
int ret = snprintf(buf, sizeof buf, "value=%d", 12345);
```

`buf` 最后只能放下 7 个可见字符和一个结尾的 `\0`。但格式化结果 `value=12345` 有 11 个字符，所以 `ret` 会返回 11，而不是 7。

这个返回值不是“实际写进数组的字符数”，而是“如果空间足够，本来应该写入的字符数”。它正好给了调用者一个判断截断的办法。

> **先记住一句话：**`ret >= 0 && (size_t)ret >= capacity` 表示输出被截断；`ret >= 0 && (size_t)ret < capacity` 表示完整结果已经写入。返回值不包含结尾的 `\0`。

这篇文章的实验运行在 macOS 14.8.8、Apple clang 16.0.0，未在 Linux 主机实测。`snprintf` 是 ISO C 标准接口；示例只讨论普通窄字符格式化，不展开编码错误和宽字符版本。

**这篇文章怎么读？**先看容量为 8 的数组实际留下什么，再看返回值怎样判断截断，最后看 `snprintf(NULL, 0, ...)` 如何提前算出所需空间。

## 返回值和缓冲区各说了一件事

把缓冲区想成一个只有 8 格的信箱，其中 1 格必须留给结尾标记 `\0`。格式化结果有 11 个字符时，信箱只能收下前 7 个，剩下的字符不会写进去；`snprintf` 同时把“完整结果本来有 11 个字符”写在返回值里。

这个类比只解释容量和返回值的关系。真实的 `snprintf` 仍然按照格式串生成字符，超出 `n - 1` 的部分会被丢弃，数组末尾会补上 `\0`。返回值也不包括这个终止符。

判断截断时，不要调用 `strlen(buf)` 和 `ret` 比较。`strlen` 只能告诉你当前数组里留下了多少字符，不能告诉你原本完整结果需要多大空间。正确比较的是返回值和传入的容量。


## 一次实验看清三种结果

下面的程序连续测试三种情况：结果太长、结果刚好放下，以及只计算所需长度而不写入数组。

```c
#include <stdio.h>

int main(void)
{
    char buf[8];
    int small = snprintf(buf, sizeof buf, "value=%d", 12345);
    if (printf("small ret=%d text=%s truncated=%d\n",
               small, buf, small >= 0 && (size_t)small >= sizeof buf) < 0)
        return 1;

    int exact = snprintf(buf, sizeof buf, "1234567");
    if (printf("exact ret=%d text=%s truncated=%d\n",
               exact, buf, exact >= 0 && (size_t)exact >= sizeof buf) < 0)
        return 1;

    int needed = snprintf(NULL, 0, "value=%d", 12345);
    return printf("probe ret=%d\n", needed) < 0;
}
```

输出如下：

```text
small ret=11 text=value=1 truncated=1
exact ret=7 text=1234567 truncated=0
probe ret=11
```

第一行中，`value=12345` 的完整长度是 11，数组容量是 8，只能保存 `value=1` 和结尾的 `\0`。因为 `11 >= 8`，所以发生了截断。

第二行的完整结果有 7 个字符，数组容量是 8，正好还有一个位置放 `\0`。`ret=7` 小于容量，说明结果完整写入。

第三行传入 `n=0` 和空指针，函数不写任何字符，只返回完整结果需要的 11 个字符。这种调用常用来先计算空间，再分配足够大的数组。

## 工程代码怎样写判断

最小的安全判断可以直接围绕返回值展开：

```c
int ret = snprintf(buf, capacity, "%s:%d", name, id);
if (ret < 0) {
    /* 编码错误 */
} else if ((size_t)ret >= capacity) {
    /* 发生截断，需要扩大空间或报告错误 */
} else {
    /* 输出完整，buf 可以使用 */
}
```

这里把 `ret` 先判断是否为负数，再转换成 `size_t`，避免负值转换成一个很大的无符号数。`capacity` 为 0 时也可以使用同样的判断，但如果传入空指针，必须遵守 `n=0` 的接口规则。

如果必须动态生成完整字符串，可以先调用一次 `snprintf(NULL, 0, ...)` 得到 `ret`，分配 `ret + 1` 个字节，再调用第二次真正写入。第二次调用仍然要检查返回值，因为参数可能在两次调用之间发生变化。

`snprintf` 解决的是“写入时不越过数组边界”，不会替你决定截断后的文本是否还能被业务接受。文件名、协议字段和日志行通常不能悄悄截断，发现 `ret >= capacity` 后应该返回错误或重新分配空间。
