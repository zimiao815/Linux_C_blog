mkdir 为什么不能一次创建多级目录？

mkdir("a/b/c", 0777) 看起来像是在创建三级目录，实际只会尝试创建最后一个路径分量 c。如果 a/b 还不存在，调用直接失败，常见错误是 ENOENT。

结论： mkdir 只创建传入路径的最后一级，父目录必须先存在。递归创建要从路径前缀开始，逐级调用 mkdir；遇到 EEXIST 不能立刻当成功，还要确认这个路径当前确实是目录。新目录的模式还会经过进程 umask 过滤。普通工具可以采用这种路径循环；对不可信路径或需要抵抗并发替换的场景，应改用以目录 fd 为起点的 mkdirat 等方案。

第一章 · 先解决问题：父目录不存在时，逐级创建再继续

单次 mkdir 只处理最后一个分量

下面的短程序只调用一次 mkdir。把 one/two 交给它时，one 不存在，系统不会替你补建 one。

C
#define _POSIX_C_SOURCE 200809L

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s DIRECTORY\n", argv[0]);
        return EXIT_FAILURE;
    }
    if (mkdir(argv[1], 0777) == -1) {
        int saved_errno = errno;
        fprintf(stderr, "mkdir %s: %s\n", argv[1], strerror(saved_errno));
        return EXIT_FAILURE;
    }
    printf("created: %s\n", argv[1]);
    return EXIT_SUCCESS;
}

递归实现要检查“已存在的路径是什么”

可复用的思路只有三步：把路径切成一组前缀；每个前缀调用一次 mkdir；如果返回 EEXIST，用 stat 确认它是目录，否则报告错误。下面的实现还处理绝对路径、重复斜杠和末尾斜杠，不使用固定长度的 PATH_MAX 缓冲区。

C
#define _POSIX_C_SOURCE 200809L

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>

static int ensure_directory(const char *path, mode_t mode)
{
    if (mkdir(path, mode) == 0)
        return 0;

    if (errno != EEXIST)
        return -1;

    struct stat st;
    if (stat(path, &st) == -1)
        return -1;
    if (!S_ISDIR(st.st_mode)) {
        errno = ENOTDIR;
        return -1;
    }
    return 0;
}

static int mkdir_p(const char *path, mode_t mode)
{
    if (path == NULL || path[0] == '\0') {
        errno = EINVAL;
        return -1;
    }

    char *copy = strdup(path);
    if (copy == NULL)
        return -1;

    size_t length = strlen(copy);
    while (length > 1U && copy[length - 1U] == '/') {
        copy[--length] = '\0';
    }

    for (size_t i = 1U; i <= length; ++i) {
        if (copy[i] != '/' && copy[i] != '\0')
            continue;

        char saved = copy[i];
        copy[i] = '\0';
        if (copy[0] != '\0' && strcmp(copy, ".") != 0 &&
            ensure_directory(copy, mode) == -1) {
            int saved_errno = errno;
            free(copy);
            errno = saved_errno;
            return -1;
        }
        copy[i] = saved;
    }

    free(copy);
    return 0;
}

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s DIRECTORY\n", argv[0]);
        return EXIT_FAILURE;
    }

    if (mkdir_p(argv[1], 0777) == -1) {
        int saved_errno = errno;
        fprintf(stderr, "%s: %s\n", argv[1], strerror(saved_errno));
        return EXIT_FAILURE;
    }

    printf("ok: %s\n", argv[1]);
    return EXIT_SUCCESS;
}

mode 传给每一次新建调用，本例固定使用 0777，实际权限由 umask 再过滤。已经存在的目录不会因为再次调用而被修改权限。

编译与运行

本次在 macOS 14.8.8、Darwin 23.6.0 x86_64 上用 Apple clang 16.0.0 编译，选项如下：

C
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g mkdir_once.c -o mkdir_once
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g mkdir_p.c -o mkdir_p

先准备一个空的临时目录，再执行下面的命令：

C
./mkdir_once one/two
./mkdir_p one/two/three
./mkdir_p one/two/three
touch one/file
./mkdir_p one/file/child

实际结果

单级程序因为父目录不存在而失败；递归程序第一次创建三级目录，第二次遇到 EEXIST 后确认目录并成功返回；路径中间的 file 是普通文件时，程序报告 ENOTDIR：

C
mkdir one/two: No such file or directory
ok: one/two/three
ok: one/two/three
one/file/child: Not a directory

实验还覆盖了绝对路径、末尾斜杠、空字符串和缺少参数。空路径返回 EINVAL；把普通文件当作父目录返回 ENOTDIR；这些分支都以非零状态结束。具体错误文本是本机 libc 的显示，稳定的是错误类别和返回状态。

这两个程序验证的是接口语义和错误处理，不是一个完整的 mkdir -p 工具。代码没有处理权限提升、网络文件系统的特殊延迟，也没有模拟恶意进程在查询间隙替换路径组件。

第二章 · 从操作系统视角理解：路径解析每次只落到一个目录项

mkdir 的目标是一个路径分量

路径 a/b/c 不是一个可以一次写入文件系统的字符串对象。内核解析它时，先从当前工作目录或根目录出发，查找 a，再在 a 中查找 b，最后把 c 作为要创建的目录项。mkdir 的创建动作只作用于最后这个名字；前面的每一级必须已经能被解析为目录。

因此父目录缺失时得到 ENOENT，路径前缀中的某一级是普通文件时得到 ENOTDIR。即使最后一级还不存在，调用进程仍需要对父目录有写权限和搜索权限；路径中间的目录也需要搜索权限。mkdir 不会因为目标目录将来要用来存放文件，就替你放宽这些权限检查。

新建成功后，文件系统为目录创建目录项和 inode，并在父目录中增加名字到 inode 的关联。目录本身还会有 . 和 .. 等特殊关系，具体内部布局由文件系统实现决定；应用只依赖“下一次按路径可以找到这个目录”这一接口结果。

递归函数如何把字符串变成前缀

mkdir_p 先复制路径，避免修改调用方的字符串。它从第一个可能结束的斜杠开始，把当前位置临时替换为字符串结尾，于是得到 /tmp/a、/tmp/a/b 这样的前缀；调用完成后恢复斜杠，继续处理下一个分量。

空前缀代表根目录，跳过；. 代表当前目录，也不需要新建。重复斜杠会产生一个已经存在的目录前缀，EEXIST 后通过 stat 确认仍是目录。循环结束后释放复制的字符串，所有失败路径都先保存 errno，再释放内存并恢复错误码。

这种写法的关键不是字符串技巧，而是把一次多级目标拆成一串可以独立检查的系统调用。每一级成功后，下一次调用才能继续向下解析。

模式、umask 和目录权限

mkdir(path, mode) 的 mode 只提供请求的权限位。Linux 和 macOS 都会用调用进程的 umask 屏蔽其中一部分，因此 0777 并不意味着最终目录一定是 rwxrwxrwx。mkdir_p 对新建的每一级都传相同模式，但已存在的目录不会被它改权限。

目录权限和普通文件的读写含义不同：进入目录需要执行权限，列出名字通常需要读权限，在其中创建或删除目录项需要写权限和执行权限共同满足。程序能创建第一级，不代表它一定能继续创建更深的下一级，因为每个父目录都要单独通过权限检查。

本篇只传 0777，让 umask 决定默认结果；如果应用有明确权限策略，应在创建接口和后续权限设置之间设计清楚的生命周期。不要把 chmod 当成对任意路径的安全补救，后文会说明路径替换带来的边界。

第三章 · 工程上怎么使用：把正常并发和不可信路径分开处理

EEXIST 不是无条件成功

多个普通进程同时创建同一路径时，一个进程可能先成功，另一个进程随后收到 EEXIST。如果第二个进程用 stat 确认该路径现在是目录，就可以把这次结果视为“目录已经准备好”。如果它是普通文件、符号链接或查询失败，就必须返回错误，不能继续向下拼路径。

本例的 stat 会跟随最后一个符号链接，因此“已有的符号链接指向目录”会被接受。这符合许多普通 mkdir -p 工具的便利语义，却不适合把路径当作安全边界的场景。若业务要求每一级都是实际目录对象，应改用 lstat 或目录 fd 方案，明确拒绝符号链接，并单独处理并发替换。

何时使用 mkdirat

POSIX 提供 mkdirat(dirfd, name, mode)，可以把相对路径的起点绑定到一个已经打开的目录。它适合服务程序逐级持有目录 fd，减少当前工作目录变化和部分路径替换带来的影响。Linux 还提供更多路径解析约束，但那是 Linux 扩展，不能写成 POSIX 保证。

mkdirat 本身不会自动递归创建整条路径。要安全地创建 a/b/c，程序仍需逐级打开或创建 a、b、c，并在每一级检查对象类型和错误。目录 fd、openat、fstatat 的系统化用法留到后面的相对路径篇，本篇的 mkdir_p 只演示普通路径工具的核心循环。

失败路径要保留原始错误

常见错误可以按发生位置理解：

  • ENOENT：父目录组件不存在，或路径中的链接目标不存在；
  • ENOTDIR：路径前缀中有一个组件不是目录；
  • EEXIST：目标名字已经存在，需要再确认它是不是目录；
  • EACCES：缺少父目录写权限或路径搜索权限；
  • EROFS：父目录位于只读文件系统。

mkdir_p 对 mkdir 和 stat 都检查返回值；stat 失败时不读取未初始化的 struct stat。错误路径先保存 errno，释放副本后恢复它，再由 main 统一输出。调用者可以据此决定重试、跳过还是终止，不会把不同原因压成一个“创建失败”。

这段实现的边界

它适合安装脚本、测试夹具和不以攻击者控制路径为前提的初始化代码。它不是竞态安全的目录创建器：stat 返回目录后，另一个进程仍可能在下一次 mkdir 前替换这个名字；符号链接也可能改变路径解析结果。POSIX 对 mkdirat 的说明正是为了解决这类“路径任意部分同时变化”的暴露问题。

如果路径来自用户输入或跨权限边界，先定义允许的根目录和链接策略，再选择目录 fd、mkdirat 以及 Linux 专用的路径解析约束。不要用“先 stat 检查，再按原路径操作”来宣称已经消除了 TOCTOU。

第四章 · 面试提炼：mkdir、递归创建和安全边界

为什么 mkdir("a/b/c", 0777) 不能自动创建 a 和 b？ 因为 mkdir 只创建最后一个路径分量，父路径必须已经存在并且可搜索。递归创建要按 a、a/b、a/b/c 逐级调用。

遇到 EEXIST 能直接返回成功吗？ 不能。目标可能是普通文件或符号链接。应查询它当前是否是允许的目录；查询失败或类型不符都要报错。

mkdir -p 是 mkdir 的参数吗？ 不是。它是命令行工具提供的递归行为，内部同样要逐级创建并把已存在的目录当作可继续的状态；C 程序需要自己实现这层循环，或调用项目已有的目录创建库。

mkdir_p 是否消除了竞态？ 没有。基于路径的 mkdir 和 stat 之间仍有替换窗口。普通并发下可以用 EEXIST 加类型确认协作，安全边界内则应使用目录 fd 和 mkdirat 等接口，并在后续操作中继续使用已确认的对象。
