# 标准 I/O 库第 8 篇：以 fgetc 的返回值解释标准 I/O 的返回值

- 核心问题：标准 I/O 函数为什么要用返回值同时表达数据和状态？
- 结论：以 fgetc 为例，返回值需要保留字节值和 EOF。先接收完整 int 并判断 EOF，再按需转 unsigned char；缩窄后再扩大无法恢复已丢信息。
- 范围：以 fgetc 说明标准 I/O 返回值契约；Linux/POSIX 常见 8 位字节环境，macOS 实测为 CHAR_BIT=8、EOF=-1。
- 用户新增偏好：正文最小代码尽量短，较长片段加中文注释。不再把完整验证工具放成满屏代码。
- 正文计划：约 20 行可独立运行的标准输入观察器；约 12 行可复用读写函数。完整 harness 单独归档。
- 不展开：UTF-8 解码、ctype、文件复制性能、fgets 长行、再次复述 EOF 标志全部规则。
- 四类需求：拿到接收类型正确写法；理解缩窄导致状态合并；知道转换顺序和错误处理；回答 unsigned char 是否能替代 int。

- 理由：用 fgetc 讲清标准 I/O 返回值同时表达数据和状态的设计，不把 int 误解成仅仅为了“占更多内存”。
