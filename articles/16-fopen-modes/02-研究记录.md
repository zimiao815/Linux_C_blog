## 关键判断与证据

| 判断 | 一手资料 | 适用边界 |
| --- | --- | --- |
| r/r+ 不创建；w/w+ 截断或创建；a/a+ 追加或创建 | POSIX fopen 的 DESCRIPTION 和 open flags 对照 | 普通文件；不跳过路径、权限等成功条件 |
| + 只改变访问方式，保留创建/截断/追加标志 | POSIX fopen；glibc-2.40 fileops.c 的 _IO_new_file_fopen | 源码先解析首字母，遇到 + 时改 omode 为 O_RDWR |
| 截断是打开阶段的动作 | POSIX open 的 O_TRUNC；Linux v6.6 namei.c 的 handle_truncate、open.c 的 do_truncate | 已有普通文件；不同于把当前偏移设为 0 |
| 描述符表指向打开文件对象，后者关联 inode | Linux v6.6 fdtable.h、fs.h | 图中 fdt、fd[3]、f_pos、f_inode、i_size；3 是示意编号 |
| a 的写入位置不被中间 fseek 改成覆盖 | POSIX fopen 的 append 条款；open 的 O_APPEND | 写入强制到当时末尾，不推导整条 stdio 记录原子性 |
| a+ 初始读取位置不可跨平台依赖 | Linux fopen(3) 手册 DESCRIPTION | 文中建议显式定位，不声明所有平台默认位置 |
| r+ 的一次短写不会替你截断尾部 | 本次 OLD → XLD 实验；r+ 不带 O_TRUNC | 仅定位后写入，不涉及读写切换 |
| wx 使已有文件失败，缺失时创建 | POSIX fopen 的 x；open 的 O_CREAT/O_EXCL | 不扩写成所有打开模式的 x 支持矩阵，不把独占创建说成持有读写锁 |
| 先检查后 w 打开有竞争窗口 | POSIX open 的 O_EXCL 原子性条款 | 没有编造竞争实验；工程结论来自两步检查/打开与原子创建的区别 |
| b 在 POSIX 下无额外打开效果 | POSIX fopen；Linux fopen(3) | 不推广到 Windows 等非 POSIX 系统 |
| fputs 成功不代替 fclose 成功 | POSIX fputs、fclose；本次文件大小限制实验 | 错误退出；fclose 后不可重试或再用流 |

## 代码与实测

`mode_probe.c` 先 fopen，后 fileno/fstat 打印 st_size；可选文本参数执行 fseek 到 0 后 fputs，最后检查 fclose。fstat 在打开之后，明确不是破坏性打开前的保护措施。

环境：macOS 14.8.8 x86_64，Apple clang 16.0.0。采用 `-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g`，零警告。

验证器 `verify.py` 在新建临时目录复制源文件，编译并运行，结束时删除测试目录。原始命令、stdout、stderr、退出状态见 `verification.json` 和 `actual-output.txt`。

- 六种模式分别打开含 OLD 的文件：w/w+ 在任何应用写入之前 st_size 已为 0；其余为 3，最终内容保持 OLD。
- 六种模式分别打开独立缺失路径：r/r+ 返回 ENOENT，退出 1；其余创建零字节文件，退出 0。
- 每轮从 OLD 开始，定位到开头再写 X：r+ 得到 XLD，w+ 得到 X，a 和 a+ 得到 OLDX。
- wx 打开已有文件报 File exists，原内容不变；创建缺失文件并写 X 成功。
- w 打开缺失父目录下的文件失败；不会建立父目录。
- r 打开目录后被普通文件检查拒绝，清理流并退出。
- stdout 使用只读 fd，输出刷新报 Bad file descriptor，退出 1。
- 在测试子进程内设置 RLIMIT_FSIZE=0，并忽略 SIGXFSZ，使错误可由 I/O 返回值观察；w 模式打开成功，fclose 报 File too large，退出 1。没有修改父进程限制。
- 缺少命令行参数时返回失败。
- `existing.sh`、`writing.sh` 均在临时目录实际执行，结果分别保存为 `existing-output.txt`、`writing-output.txt`，正文直接嵌入。

## 实验限制

没有在 Linux 主机运行，也没有跟踪实际系统调用次数。Linux/glibc 内部行为由指定版本源码说明。未运行权限竞态、跨文件系统、网络文件系统、并发追加、断电、内存不足或信号恢复实验；不能用本实验推导这些情况的可靠性。

模式允许读写的语义由规范支撑；实验不尝试对只读流强行写入，也不扩展为更新流交替读写教程。
