# 研究记录

POSIX fdopen 将已有描述符关联到流；流模式必须被原打开方式允许；
新流继承 fd 偏移，"w" 和 "w+" 不截断。接口属于 POSIX。
Linux man-pages 明确写明 fd is not dup'ed，关闭流会关闭 fd。

成功后的关闭责任交给 fclose；失败没有建立流，调用者仍处理原 fd。
工程函数额外约定“无论成功失败都接管并清理”，不能把这个约定误写成
“fdopen 失败会自动关闭 fd”。

实验在 macOS 14.8.8 x86_64、Apple clang 16.0.0 执行，未在 Linux 实测。
常规成功路径实测；ENOMEM 路径通过独立测试构建替换 fdopen 注入。
写出错误用已关闭读取端的管道验证，测试进程忽略 SIGPIPE，以便观察 EPIPE。
未故意使用不兼容访问模式，未实际耗尽系统内存。
逐项编译选项、退出码与输出见 verification.json。
