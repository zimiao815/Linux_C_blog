# 研究记录：`unlink` 与 `rmdir`

## 核心事实与依据

| 技术判断 | 直接资料 | 核验结果 |
| --- | --- | --- |
| `unlink` 移除目录项、减少目标文件链接计数 | POSIX unlink；Linux unlink(2) | 正文区分名字与对象 |
| 符号链接用 `unlink` 删除链接自身，不删除目标 | POSIX unlink；Linux unlink(2) | 有效、悬空链接均实测成功 |
| `rmdir` 只删除空目录，非空返回错误 | POSIX rmdir；Linux rmdir(2) | `full/child` 和隐藏文件均使 rmdir 失败 |
| 删除最后名字后，fd 或映射仍在时内容释放延后 | POSIX unlink；Linux unlink(2) | 打开后 unlink，fstat nlink=0，read 仍成功 |
| 删除权限检查父目录写和搜索权限，而非目标文件写权限 | Linux namei.c may_delete；Linux unlink/rmdir 手册 | 0444 文件可删，0555 父目录删除失败 |
| `unlink` 目录在不同环境错误码可能不同 | POSIX unlink；macOS 实测；Linux unlink(2) | macOS 为 EPERM，Linux 常见 EISDIR |
| Linux VFS 分开进入 `do_unlinkat`/`vfs_unlink` 与 `do_rmdir`/`vfs_rmdir` | Linux v6.6 fs/namei.c | 图与正文限定源码路径 |
| ext4 删除目录前检查为空，文件删除降低 nlink | Linux v6.6 ext4/namei.c | 对应 ext4_empty_dir、drop_nlink |
| `remove` 统一文件和目录入口但不递归 | Linux remove(3) | 表格中作为可选统一接口 |
| `unlinkat` 可相对已打开目录 fd 工作，AT_REMOVEDIR 选择目录语义 | POSIX unlink；Linux unlink(2) | 正文说明固定起点不等于锁定名字 |

## 实测记录

2026-10-05 在 macOS 14.8.8 / Darwin 23.6.0 x86_64 使用 Apple clang 16.0.0，严格参数 `-std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -O0 -g` 编译两个示例，无警告。

- `unlink empty`：退出 1，macOS 文本为 Operation not permitted，目录保留。
- `rmdir full`：退出 1，Directory not empty，子项保留。
- `rmdir dir-link`：退出 1，Not a directory；`unlink dir-link`：退出 0，只删除链接名。
- 删除 `full/child` 后 `rmdir full`：退出 0。
- `unlink_open note.txt`：输出 `after unlink: nlink=0` 和原内容，退出 0，路径不存在。
- 缺失路径、普通文件调用 rmdir、权限父目录、只读文件和隐藏子项均覆盖失败或成功分支。

完整输出和退出码写入 verification.json 与 actual-output.txt。Linux 6.6 部分使用固定源码核验，没有把 Linux 运行结果伪装成本机实测。

## 实现边界

`delete_entry.c` 不先查询类型，而是让接口返回结果，避免检查与删除之间增加无意义的窗口。`unlink_open.c` 对 read、fstat、close、stdout 逐一检查，并在 EINTR 时重试 read。没有注入 close、输出故障、网络文件系统确认回复丢失或恶意并发替换。

实验对象在临时目录中创建。权限测试在非特权进程下执行；若运行环境为 root，verify.py 会标记该项跳过，不能据此声称完成权限拒绝实测。
